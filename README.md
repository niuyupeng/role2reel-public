# Role2Reel Public

**把人物、剧本和已有分镜，变成有因果、有空间、有摄影依据的完整视频提示词。**

[English](README.en.md) · [快速开始](#快速开始) · [完整示例](#先看它交付什么) · [验证记录](EVALS.md) · [下载最新版](https://github.com/niuyupeng/role2reel-public/releases/latest)

[![Validation](https://github.com/niuyupeng/role2reel-public/actions/workflows/validate.yml/badge.svg)](https://github.com/niuyupeng/role2reel-public/actions/workflows/validate.yml) [![MIT](https://img.shields.io/badge/license-MIT-317873.svg)](LICENSE)

一个可独立安装的 **Codex Skill**。既能从人物和对白开始，也能直接接住已定稿的剧本、分镜或提示词，只完成你当前需要的那一步。

**三条常用路径**

| 你已经有什么 | 让它做什么 | 交付什么 |
|---|---|---|
| 剧本与人物设定 | 整理所需资产，内部拆镜与匹配摄影 | 分段资产清单、完整视频提示词、剪辑区间 |
| 已定分镜或提示词 | 只补焦段、光圈、主焦、运镜与执行细节 | 保留原对白和时长的完整新版 |
| 人物线索或对白草稿 | 推演不同的人生可能，或把场景写得可演 | 供作者选择的人物来路，或自然的动作与对白 |

## 快速开始

在 Codex 中发送：

```text
$skill-installer 从 https://github.com/niuyupeng/role2reel-public 安装仓库根目录的 Skill，名称设为 role2reel-public。
```

安装后在下一轮输入 `$role2reel-public`；若尚未出现，重新打开会话。也可以下载 [最新 ZIP](https://github.com/niuyupeng/role2reel-public/releases/latest)，按 [手动安装说明](docs/installation.md) 放入技能目录。

**先做一个小任务，不需要先初始化工程，也不用准备一整套人物档案。**

```text
$role2reel-public
给我一份9秒、三个镜头的简易分镜：
花店店员在一张素桌前举起唯一的空花瓶，说“还是空的。”
朋友接着说“还是空的。”两人笑了，她把花瓶放回桌上。
两句都保留原文，不加台词或道具；只有自然现场声，无字幕、无配乐。
这是用于讨论的文字分镜，目前没有照片，不需要生图。
```

你应得到能讨论和修改的镜头表：时间合计9秒、两句归属正确、花瓶始终只有一个、动作有起因与结果。缺照片应如实说明，不应阻止文字草案，也不应声称素材已绑定。

普通文字使用需要能够读取本地 Skill 的 Codex。可选的初始化和校验脚本需要 Python 3.11+；涉及 YAML 的脚本还需要 PyYAML。图片、Word 和视频输出取决于当前环境中实际可用的工具，仓库没有捆绑模型额度或视频生成服务。

## 先看它交付什么

### 已定稿 → 参数齐全、可整段复制的提示词

[查看完整输入与实际输出：修理间的钥匙](docs/examples/camera-segments.md)

故事只有12秒：林递出一枚钥匙，周接过；随后周开箱，林看见成功后点头。原句“试试这个。”保持不变。

| 生成段 | 生成素材 | 前置余量 | 核心与推荐保留 | 后置余量 | 剪入正片 |
|---|---:|---|---|---|---|
| G01 递钥匙 | 8秒 | 0–1秒 | 1–7秒 | 7–8秒 | 0–6秒 |
| G02 开箱 | 8秒 | 0–1秒 | 1–7秒 | 7–8秒 | 6–12秒 |

正文同时交代动作和摄影。例如第一段从35mm关系中景切到65mm操作特写，主焦从说话者转为手指与钥匙接触处；背景能交代空间，不强求与手部同样锐利。两段都在动作完成后收束，可以独立生成和剪辑。

这是实际文本试做。参数是制作起点，照片未提供，平台和动态效果未验证；**16秒素材裁入12秒正片，不把生成余量算进正片。**

### 稀疏人物线索 → 作者可选择的三种来路

[查看完整输入与实际输出：邮差与退信](docs/examples/life-paths.md)

同一个“把退信夹进手册”的动作，可以分别连向想被认可、保护别人的解释空间、寻找归属。每条都会说明解释了什么、什么仍未知；候选不会自动变成角色事实，决定权留给作者。

两例的输入、原始输出、所用版本、复核范围和不足见 [文本试做记录](docs/text-trials-2026-10-27.md)。

### 多人物、多道具与跨场景

[查看完整英文案例：工作间的物品交接](docs/examples/workshop-handoff.md)。三个人、两处空间、两枚编号物品和一个袋子，分三段生成；每段先列资产，再给完整摄影与动作正文和剪辑区间。物品归属、人物看见信息的先后、留在画外的角色都要保持一致。

更多复杂请求、重复试做、不可执行时长的处理和实际局限见 [多轮复杂案例记录](docs/complex-trials-2026-10-27.md)。这里公开原始答案，方便检查具体行为，不用软件测试数代替创作结果。

## 为什么这样组织

- **保护原稿。** 已确认的对白、人物关系、关键动作、时长和镜界继续有效；“更电影化”不等于改写授权。
- **先让故事成立。** 谁看见什么、何时理解、为什么反应；物品如何接触、受力、移动和停稳，都进入镜头设计。
- **让摄影服务观看任务。** 按尺度、画幅、距离和景深匹配镜头；相机品牌不等于固定题材，手部近景与环境大全景各有重点。
- **区分镜头与生成段。** 一个段落可以包含多个镜头；段内清楚，段间保持故事和状态连续，不强求首尾姿态逐帧匹配。
- **资产有职责。** 身份、服装、场景、道具、声音分别继承；参考库不等于当镜全部入画。2K/4K以实际像素和目视复核为准。
- **进入你所在的阶段。** 简易表直接核对原稿；需要可持续追溯的正式工程时，才启用版本、哈希和机器审计。

## 更多工作方式

| 任务 | 示例调用 | 方法 |
|---|---|---|
| 摄影参数快补 | “不改原稿与时长，把每镜焦段、光圈和主焦补进完整正文。” | [摄影匹配](references/shot-camera-matching.md) |
| 资产优先 | “先列全片需要的角色、场景、道具和生图提示词；已定身份直接复用。” | [资产优先制作](references/asset-first-production.md) |
| 对白修订 | “保留剧情，让两个人根据各自知道的信息行动和说话；保留有用的停顿与重复。” | [人物与对白](references/scene-dialogue.md) |
| 人物来路探索 | “同一个现状给三条不同的过去，先供我选，不替我锁定。” | [命线反演](references/fatecasting.md) |
| 已有角色视觉资产 | “只修当前这张图的材料和受光，保留身份与构图。” | [角色视觉](references/character-visual-development.md) |
| 音乐IP/MV、封面、局部视频修复 | 说明已有素材、允许修改的范围和需要的产物 | [扩展工作流](references/workflow-routing.md) |

需要 Word 时，明确要求可编辑 `.docx`；完整段落提示词放在普通正文中，方便一次复制。字幕、音乐、旁白和画幅跟随当前项目约定，不把某一项目的风格强加给所有人。

## 已验证到哪里

| 证据 | 能说明什么 | 仍不能说明什么 |
|---|---|---|
| Windows / Ubuntu，Python 3.11 / 3.13 自动检查 | 脚本、结构、引用、打包等约定在所测环境通过 | 创作一定好看，或媒体平台一定照做 |
| 独立虚构文本试做及公开原始输出 | 可检查时间、对白、人物选择权与执行信息 | 跨模型成功率、真实用户采用率 |
| ZIP白名单、隐私扫描与人工检查 | 发布范围经过审查，公开包与内部版隔离 | 自动扫描已证明绝对没有语义隐私风险 |
| 图片/视频/表演 | 本次未新增验收证据 | 不宣传已验证的成片质量或“一天一集”保证 |

详见 [当前评估与历史边界](EVALS.md)。欢迎提交带完整输入、实际输出和期望差异的 [可复现问题](https://github.com/niuyupeng/role2reel-public/issues/new/choose)，请先移除私有材料。
