# Maintaining the public edition

## Publication boundary

This is the independently installable public edition, invoked as `$role2reel-public`. Keep its directory separate from any internal `role2reel` installation. It is self-contained: do not import sibling skills, private project profiles or internal history merely because they are available locally. Use the project context supplied for the current task. Public updates must not overwrite the internal edition.

Project work stays in its local project workspace. Updating this general-purpose skill authorizes reusable methods, not publication of project names, stories, lyrics, media, raw logs, private research or conversation history. Read [publication boundary](publication-boundary.md) before exports, branch integration or repository updates. Project style, aspect ratio, languages and delivery layouts come from local configuration; templates are configurable examples, not universal private-project defaults.

When improving the skill from user feedback, apply [feedback generalization](publication-boundary.md#generalize-project-feedback): retain the transferable decision method and its limits, while keeping source cases in the private project.

## Integrating branch improvements

When asked to consolidate branches or improve this skill from prior work, inspect all changed paths and their history, not just character-design files. Check both commit ancestry and retained content. Map each useful detail to its active route, reference, template or check; classify duplicates, superseded/conflicting rules and historical evidence explicitly. Preserve original evidence and explain exclusions. A successful Git merge alone does not show that the skill can discover or use the improvement. Do not activate old workflows just because their files were merged.

## Research languages

For research into character-design skills, creative methods, music/video references or provider workflows, apply the project-specific language scope in [research language guidance](music-research-platforms.md#中英文检索与语言适配). Use the relevant research languages when external research is needed; distinguish source language, audience language and executable prompt language. Do not treat a past project’s language preference as a universal restriction.
