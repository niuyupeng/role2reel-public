# 剧本到完整图片资产：自动执行与断点恢复

适用于用户提交剧本并要求“自动做齐资产/一键出角色、场景、道具、分镜图”。这是由调用本技能的助手执行的编排流程，不是脱离模型、工具和授权也能运行的独立生成程序。只要求修改本技能或提示词时，更新工作流，不启动媒体生成。

## 执行范围

保留原剧本、台词、情节、角色关系和用户已定美术/比例。先读剧本是为了拆资产，不是先重写剧本；已给剧本且只要求资产时，不擅自重写故事。已有身份母版优先复用。普通可逆的构图、文件名、镜头拆解和背景细节自行处理并记录，不每张图等用户批准；涉及改变主角身份、剧情结局、明确设定冲突或缺少关键输入时只问必要问题，同时继续不依赖它的部分。

收到剧本不自动等于请求所有媒体：仅校对/评审/修改剧本依旧遵守原路由。用户请求自动制作资产后，不能停在计划、清单或提示词。实际使用当前可用的图像生成/编辑工具，读其技能，按下列依赖顺序保存并检查图片。不因参考资料提及外部服务就安装、订阅或调用收费API；当前工具不可用时，记录阻塞与未生成项，不伪称图片已完成。最终视频生成与平台提交不包含在本图片工作流中。

## 0. 拆解与建账

保存原剧本及版本/hash；按场次/动作节拍建立稳定ID：角色C001、造型L001、道具P001、场景E001、镜头S001。合并同一对象的别名，但不把身份不同的人或相似道具合并。逐镜记录出场角色/造型、场景、持物与状态变化、说话者、表情、动作起点、视线、时间与声音。歌曲无源音频或明确边界时，时间仅作暂定，不能伪造听辨结果。

先读[逐镜参考决策与覆盖检查](shot-reference-planning.md)，为开场、中段、收尾分别列出可见状态，选择单首帧、首尾帧、分镜关键帧序列或组合参考，并记录理由与平台能力待核验项。

先形成资产需求表与简短镜头计划，用于确定要做哪些图；正式镜头图在上游角色和空间资产可用后生成。每条需求必须有剧本依据或标为最小制作假设。背景通用杂物可并入场景；被特写、持握、传递、重复出现或影响因果的物件必须有独立道具ID。无道具的剧本可标“不适用”，不能为了齐全凭空加入话筒或道具。

从[清单模板](../assets/templates/script-asset-manifest.json)实例化任务。资产记录包含asset_id、kind、entity_id、revision、source_script_refs、depends_on、shot_ids、purpose、allowed_properties、excluded_properties、prompt_file、reference_files、file、hash、status、visual_review、replaces。不存在的路径填null；不要先造一个文件名就标完成。

### 按视觉职责拆资产

独立对象ID用于跟踪同一对象，不等于必须新增一张图片。先检查现有图实际看清了什么，再补镜头需要而尚未覆盖的依据；同一合格图可承担多个确实可见的职责，但不能靠重复计数满足用户要求的独立交付文件数。用户明确要求的数量、用途和独立文件优先，不能擅自缩成最小包。

| 视觉职责 | 需要看清的关系 | 不能用来替代它的材料 |
|---|---|---|
| 母空间 | 总体布局、稳定地标、子对象位置与尺度、光源 | 只有气氛而无可行动布局的装饰图 |
| 独立物件外形 | 物件自身轮廓、结构、连接点与必要开合面 | 物件在大场景中无法辨认的远景 |
| 内部空间 | 同一对象内部的出入口、操作区、容纳尺度和行动余地 | 看不清这些内部关系的外观图或母空间机位变体 |
| 外围环境 | 建筑或物件与周边地形、通路、出入口和尺度的关系 | 只有内部装饰的图 |

这四种职责是判断工具，不是四张图的配额；没有内部戏就不强制设计内部。按需用现有 `depends_on` 记录母空间、子对象和子空间的关联；外观与内部不能各自设计成结构不相容的对象。某物从固定设施变成可移动物时，保留同一身份，交代支撑、连接和状态变化，不另造无关型号。

每张待生成图在 `purpose` 中写明职责、主体和应看清的结构；验收时按该职责检查。要求独立物件、内部空间或外围环境时，不得交付几张母场景变体冒充齐备。用户要求独立图片时逐文件保存，联系表或拼图只作额外总览。

### 生图摄影与输出规格

静帧参考只选定一个构图与焦点状态，不把拉焦、跟焦、镜头移动或逐秒动作写成同张图片的执行过程。单件道具的中性展示背景只负责呈现，不自动成为故事中的桌子或柜台；原稿明确禁止额外家具、人物或道具时，场景方案也遵守该边界，不能为了方便承托就补一件家具。已认可身份优先直接复用，制作新构图时只改变本次授权属性。

摄影要求从实际图片生成/编辑正文开始落实，按[摄影与光影设计](cinematography-lighting.md)选择，不留到视频阶段才补。用户要求专业摄影参数时，每张摄影参考写明已定相机系统/感光面与画幅、真实焦距、工作光圈T/f值、主焦与所需景深、机位和光源；按构图需要补主体距离、机位高度和主体背景距离的制作估算。关系全景重空间可读性，表演近景重眼睛和口部，接触/道具图重接触点、支撑与材质；不统一套极浅景深。后续视频镜头继承对应图的摄影逻辑，不在同一机位状态下无故换参数。多视图按格说明不同机位；纯俯视/轴测制作图注明投影用途，不编造摄影EXIF。快门、ISO仅在曝光或运动表现需要时补；静态图不把帧率当作分辨率。

全部图片类型都读取用户或项目已锁定的比例与目标像素宽高，直接写进生图正文，并设置工具实际提供的尺寸选项。保存后核对原始输出及最终文件的真实宽高；仅提示词写有“2K”或文件名带尺寸不能证明达标。总览拼贴与每格有效像素分开检查；要求独立素材达到规格时逐文件核验，不能用总图尺寸代替单格尺寸。若需裁切、补边或放大，记录处理及原始尺寸，保持关键构图、身份与比例；放大不能冒称原生生成或新增真实细节。未达到已锁规格就明确未达标，不静默降低要求。已有身份母版不因新的输出尺寸要求自动重做，新生成的衍生图遵守本次输出规格。

用户指定升至2K/4K等档位时，先将档位落实为本任务明确的像素宽高，区分新图原生高分辨率生成与已有图的超分辨率处理。按工具实际能力执行，不能只在提示词添加分辨率词。对已认可图片升清时保留原文件，另存衍生版并复核身份、比例、构图、纹理及光影，避免新增伪细节或过锐化；未完成实际升清不能称已升级。默认档位、何时升档与具体尺寸沿用本地用户要求，不把某项目的2K/4K口径设为所有任务通用标准。

只有画幅比例、没有像素尺寸或分辨率档位要求时，记录“目标像素未锁定”和实际宽高；可以按用途提出并注明尺寸假设，不能把仅符合比例称为满足一个不存在的2K/4K目标。主图的尺寸、模型读取副本的尺寸和交付尺寸分别记录，压缩给模型读取不覆盖原始素材，也不冒充最终清晰度提升。

人物细节优先从生成源图的取景、焦点和材质建立，再用超分完善输出；仅增加像素不能证明恢复了源图未含的真实细节。要求皮肤毛孔等细节时，安排有实际用途的独立面部近景，在合适尺度核对非重复的毛孔、细小绒毛、自然肤色变化与眼唇结构，不把整幅多人/多格图达标当成每张脸达标，也不让全身远景出现宏观可数的毛孔。动物按物种检查毛发方向与层次、胡须、眼鼻细节，不套用人类皮肤或强制人脸修复。避免磨皮蜡感、玻璃眼、均匀噪点毛孔、边缘光晕和假毛丝。保留已定身份；强生成式细节候选须与母版对照，不自动替换为已认可身份。工具库存核查分开记录程序、依赖、模型权重和实际小样；仅有节点模板、安装包或目录不算已可运行。

材质复核同时看整图和原尺寸局部。重复弧线、迷宫状浮雕、连续糖衣般高光可能只是被锐化的伪纹理，不能因细节更多就通过。接入真实材质照片时只继承其已声明的材质与受光职责，不换掉身份和构图；参考照片、相机型号或超分都不保证纠正失败。连续修订没有改善时保存失败证据、降低夸张纹理指令或更换有依据的源图策略，不继续把失败图放大冒充细化成功。另一视觉模型的“通过”只是辅助意见，需与实际目视缺陷分别记录。

## 1. 角色基础图先行

先复用已确认的身份母版；缺少表情板、三视图或本次摄影参数，不自动触发人物重设计或重做整套人物图。只有本次镜头确需且旧图未覆盖的视角、造型、动作或表情才补相应依据，并保留身份。以下两图合同仅用于本次需要新建或明确交付的完整角色基础包，沿用[music-assets.md](music-assets.md)与[造型规则](character-visual-development.md)：

- C001-体态档案-v01：默认16:9，左约38%超大身份肖像，右约62%正面、90度侧面、背面全身，同尺度同基线、完整身体、浅灰背景、无文字；用户指定版式优先。保留本次指定造型；另需简化身份底稿时采用白T白短裤或该动物适合的自然形态，不改变固有肤色毛色，不覆盖既有服装母版。
- C001-独立表情-v01：另一张16:9，可用大中性身份肖像＋六个小表情，依实际剧情选中性、委屈、惊讶、愤怒、坚定等，避免全微笑；讲话/演唱检查张闭嘴与物种结构。按物种调整头肩取景。

新建完整基础包时，先目视检查第一张的身份/体态，再用同一身份生成表情；此模式交付两张，可复用合格旧图。直接复用已定身份时记录实际使用文件即可，不为补齐此包制造新任务。新生成的视觉候选可供同一草稿包继续派生，标为provisional_design，不把助手目视通过写成用户已批准设定。

## 2. 剧情服装与状态

先通读整个剧本，再按角色汇总完整服装与配饰清单，不只看第一场。读取时间/季节、场合、剧情明确的换装、穿脱、湿干、污损、伤后变化及相关动作；歌词中的比喻（如“换帽子”）不自动当成真实换装。未写明而制作必须确定的部分沿用已有设定，或补最小视觉假设并标记，不声称是原剧本事实。

### 数清套数与状态

每个角色分别报告：独立服装套数、各套穿着/损坏状态数、可拆配饰数、关联手持道具数；不把同一套跨场出现重复算成新衣服。用look_id表示整套设计，用look_state_id表示穿脱、湿污、破损等可见状态。每套列出上装/内搭/下装/鞋履/帽子/首饰等实际存在的组件、颜色、材质、穿法、角色ID、依据场次、适用镜头、首次出现与改变原因。部件不适用时留空，如动物自然形态不能被迫穿人类鞋裤。

清单entities.looks逐项保存：look_id、character_id、components、accessory_ids、source_script_refs、design_basis（explicit/existing_reference/provisional）、style、states；states记录look_state_id、变化、起止场次/镜头、prop_ids、reference_asset_ids。shots中绑定character_id＋look_id＋look_state_id及prop_ids。剧本修订后重算受影响的状态与镜头，不能沿用过时造型。

### 每套都要有实际造型图

为每个实际使用的独立造型生成或复用至少一张穿着造型图，使用[剧情造型模板](../assets/templates/character-look-prompt.txt)。已确认身份图清楚展示所需穿着时可直接兼任，不强制另做一张。新建图默认16:9横版，同一角色正面、90度侧面、背面全身；必要细节另图补充，用户已定画幅优先。身份、体型和物种来自同一基础母版，衣服按剧本年代、场合、行动需求及项目美术设计；遵循项目美术规范，不因换装换画风。不能只出衣服平铺图而没有角色穿上后的样子。

每个影响可见画面的look_state_id也需合格状态参考；状态差异很小时可对基础造型局部编辑或复用已展示该状态的图，但要注明依据。复杂衣服的层次、扣合、尾部开口、鞋履与饰品可补拆解/局部特写；本次明确要求完整角色基础包时，这些附加图不能抵扣其中的基础档案和独立表情。无衣服的自然动物也记录“自然形态”造型并绑定现有合格图，不凭空换装。

### 服饰与道具连续性

把可拆配饰作为组件绑定造型；帽子、眼镜、包等被取下、传递、持握或成为剧情特写时，同时建立道具ID，共用同一设计版本，避免头上帽子与手中帽子变成两件不同物品。手持道具另做道具图，不永久画进造型母版。多人同场时记录比例差异，必要时出同尺度对照图。

验收检查：实际套数与需求表一致，所有状态都有参考或明确阻塞；无漏鞋/饰品、衣层不可能穿在一起、换装换脸或动物关节/尾部被错误封住；镜头服装与状态映射完整。基础白T不得自动代替剧情造型，也不能把剧情服装反写为身体身份。只写衣服描述或“以后补图”不能称造型资产完成。

## 3. 道具资产

重要道具检查下列两类视觉依据，使用[道具提示词模板](../assets/templates/prop-reference-prompt.txt)按需生成；已有合格图能看清相应要求时复用，不按每件两张机械凑数：

- P001-外形结构：单个道具多视角（正/侧/背或顶部，以结构需要为准）与关键细节，统一大小比例、材质、图案、正反方向，干净背景；不得画成多个不同型号。
- P001-使用状态：实际持握/接触/开合/破损等剧情状态；锁定哪只手、接触点、与角色相对尺寸。动作有多个阶段可另存状态图，不把多个时间阶段堆进单幅首帧。没有持握/变化的固定物件不强制补状态图；连接结构或关键材质仍看不清且影响镜头时，再补细节依据。

不对无脸物件制造“表情图”，不强制所有物件正侧背都能提供有用信息。重复出现的同一道具复用ID；必须精确的文字/数字另列文字层，不能让生成模型随机文本成为剧情证据。

## 4. 场景资产

场景图遵循项目已定画幅（如16:9横版），按实际镜头需要选用空镜主图、空间关系图（俯视/轴测/反向机位）、其他机位与日夜/天气/损坏状态图；沿用同一画幅到下游分镜关键帧。没有已定比例时按交付用途选择并说明；提示词写明实际画幅，工具有画幅参数时同时设置；落盘后记录实际宽高并核验。若工具只返回近似比例，记录实际尺寸和偏差，不能称已精确符合；需要重新构图或用户允许的适配，不拉伸或随意裁掉关键空间。

每个叙事空间检查下列两类视觉依据，使用[场景提示词模板](../assets/templates/scene-reference-prompt.txt)按需生成；主图已经清楚覆盖简单空间关系时，可记录依据并复用：

- E001-空镜主图：无角色，展示实际入口、门窗、主要道具、前中后景、光源与材质；继承项目画幅和画风。
- E001-空间关系：同一场景俯视布局/轴测图或反向机位，解释相邻镜头的门窗位置、桌椅间距、角色走位区与镜头轴线。布局图可以作为制作图单独标注，不能当最终画面；无文字要求时用外部文档说明ID，不让标注进入正片。

空间关系图必须由同一布局派生，不能把第二张重新设计成另一间房。剧情确有日夜/损坏/天气变化时记录状态，按逐镜覆盖需要补图，稳定建筑结构。涉及反打或移动揭示时必须明确新可见空间，不用装饰空镜代替连续性依据；不因存在日夜、灯光或开合变化就一律加图或一律省图。

## 5. 分镜图与实际生成单元

生成场景参考时就按[摄影与光影设计](cinematography-lighting.md)固定空间与光源；到本阶段使用同一[场景摄影表](../assets/templates/scene-camera-lighting-plan.md)补齐表演走位、构图、焦点、运镜起止与切点。反打沿用场景坐标中的光源，不重新布置成另一间房。这里只完善必要制作假设，不改写上游故事；画幅与画风从本地项目配置读取。

角色、造型、相关道具和空间依赖都已目视通过后，按逐镜参考方案生成或复用所需单幅起点、关键中段、细节与终态图。不是每镜都强制首尾两图，也不能一张开场图覆盖所有复杂过程。先拿一张代表性合成镜头检查身份、服装、比例、空间、美术和接触关系，再扩展余下镜头；这一步由助手检查，不默认增加用户审批。

关键帧展示单一可执行动作起点：谁在何处、哪只手接触哪个道具、视线向谁、嘴是否准备开口。按故事状态切镜，不按歌词一行一图；相邻镜头承接位置、轴线、持物、光线与情绪。清楚绑定参考图只提供身份/服装/空间/表情的哪一部分，不无差别上传全部参考。

需要结束状态或揭示时另存尾帧；实际视频续接仍优先用用户生成并检查的结束帧，不把计划图冒充视频真实末帧。可额外交付分镜总览板，但必须同时保留单镜头图，总览板不代替普通I2V首帧。对白与唱歌的口型要求写入逐镜提示词，静帧通过不能声称动态对口型通过。

## 6. 检查、修复与继续

逐张记录实际检查：角色身份/解剖、表情、构图完整性、衣服/道具状态、接触与支撑、空间轴线、画风、文字污染及镜头用途。未看过图不能标视觉通过。状态统一用planned → generated → reviewed；rejected与blocked分别记录原因；旧表的needs_generation映射planned，available只代表存在，须补视觉检查后才映射reviewed。

发现局部瑕疵优先定向编辑，不推倒全部资产。同一问题连续两次修复仍无进展时，保存失败候选和原因，标记受影响的下游为blocked，继续可独立完成部分并报告；不要无限重抽或为了流程变绿放宽标准。身份/服装/布局上游修订后，检查所有依赖镜头，标记needs_recheck，不重生成无影响的素材。

每个实际文件保存后更新清单、实际提示词、所用参考和版本。中断后先读清单、核对文件存在及hash，跳过已检查且依赖未变的资产，从最早缺失依赖继续；仅文件存在不能跳过验图。

## 7. 完成交付

按角色、造型、道具、场景、镜头分别存目录；图片名称包含稳定ID、类别、状态/镜号、版本。交付一个可打开的图文入口，展示本次实际交付图片（完整角色基础包的两图分别展示），附全部文件清单、完整提示词及每个视频生成单元的上传说明：哪张主图、哪些辅助、音频用途、继承/排除项、时长和衔接。

收尾必须检查[逐镜参考方案表](../assets/templates/shot-reference-plan.md)的状态覆盖和每个生成单元的输入清单；分别报告计划完成、图片齐备和动态验证状态。

仅当所有本次必需项都实际存在且目视通过、逐镜依赖齐全，才称“图片资产包完成”。复用项、待选视觉候选、暂定时间、阻塞项、动态未验证项分别说明。空清单、模板、计划和仅文字分镜都不等于完成。项目另有归档技能时执行其收尾；通用技能不硬编码私人项目目录。
