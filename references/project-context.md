# Persistent project context

Use this route when resuming a named story world, consolidating group files, learning from earlier episodes, or preparing prompts from supplied dialogue/audio. This is a project-local memory and provenance layer, not a replacement for the existing creative stages. Keep only reusable methods and empty templates in the skill repository. Keep a named project's section, scripts, chats, media and source identifiers in its local workspace.

## Select the project before retrieving detail

Resolve spoken aliases against a confirmed project name and local source directory. A shared workspace can contain several productions; the current folder or last task does not establish which cast or visual bible applies. Record a stable project ID and a continuity key (series, season, adaptation, period or branch as needed). Same-name roles and repeated episode numbers are not identity evidence. A design sheet for one production is not a fallback for another.

Use `assets/templates/project-context.yaml` as an optional local index. An existing equivalent index need not be migrated just to match the template. Read its relevant underlying sources before making consequential claims; the index is a retrieval aid, not self-proving evidence.

## Inventory and inspect sources honestly

For each source record its location, revision or immutable binding when available, archive member if applicable, relevant locator, access date and reading scope. Distinguish listed filenames, full text, a visible chat excerpt, inspected stills, sampled video, full video and actually heard audio. A document mentioning an attachment does not mean the attachment was inspected. A play button, title, description, thumbnail or automated transcript does not prove the clip was watched or heard.

Search group records only within the authorized group and relevant subject. Confirm the actual group name and the file/message association through the visible UI or an authorized export. A local messaging download folder can contain multiple conversations: without evidence, label a file's group association unverified. Do not decrypt databases, extract keys or bypass login/verification to fill a gap. Continue with accessible sources and report what remains inaccessible. Keep chat participants and raw messages local; no messaging or uploads are authorized by a research request.

Inspect archive members without executing their contents. Keep member identity and content hashes when variants matter. File modification time and a name such as `final` do not establish the selected version. For duplicate downloads, compare content; preserve conflicting versions and the reason one applies.

## Retrieve the working example when resuming a workflow

When the user says a delivery pattern was already established, retrieve an applicable actual deliverable and the related feedback before rebuilding its structure or re-estimating its timing. A summary saying “learned” is only a pointer. Compare the example with the current contract: what still applies, what was corrected, what was local to that task, and what is unverified. Keep this small comparison in the project memory and route the inherited decisions into the current artifact. If no example is accessible, proceed with the current explicit requirements and state the retrieval limit; do not invent prior acceptance or require the user to repeat accessible decisions.

Deduplicate shared messages in forked chats. Treat unavailable message bodies and referenced-but-unopened attachments as unread, even when an index exposes their title. “Continue,” acceptance of a repair direction, a generated file, and assistant self-review do not establish acceptance of the resulting media. A later complaint may invalidate the earlier interpretation. Preserve the exact artifact and scope of any genuine acceptance.

## Separate facts, performance and author decisions

Maintain distinct claim statuses: source-observed, explicit-author-choice, creative-proposal, disputed, superseded and unknown. Record the scope and source for each. A character's boast, rumor, joke, impersonation or unreliable narration establishes that performance, not necessarily its literal biography. Repeated assistant prose cannot confirm itself. Choosing a life-path branch does not approve every detail in its later biography.

Preserve coexisting continuities. A later file or release is not automatically a retcon. An original screenplay and a released adaptation can each govern different work; record which governs the requested task, and show consequential conflicts rather than silently averaging them. Use [world grounding](world-grounding.md) for disputed universe facts and [source truth](source-truth-gate.md) for script-to-shot fidelity.

For performance learning, connect a located scene to the observable cue, action, words, relationship, pressure and consequence. Mark interpretations as interpretations. Learn tactics and limits rather than copying catchphrases or treating an isolated gag as a permanent personality. Do not transfer a reference's morality, species, costume or hidden plan unless supported and applicable.

## Build a small task-specific handoff

Retrieve the selected continuity, relevant character behavior/knowledge, exact dialogue ownership, applicable visual/voice assets, world constraints, approved preferences and unresolved blockers. Do not paste the entire archive into every prompt.

When audio and text are supplied, bind the actual audio file and its version; measure its duration and check words, speaker changes, pauses and non-speech sounds against the supplied text. State its authorized purpose: preserve the original track, use timing/lip-sync only, use voice identity only, or another explicitly scoped use. These purposes are not interchangeable; a timing reference does not authorize voice replacement or cloning. The current user's clear instruction can authorize use of a newly supplied source without an old approval record, but that is not acceptance of a newly generated result. Keep source-local time, output time and shot-local time distinct. Text-only timing is an estimate. Flag a consequential audio/text mismatch; do not silently rewrite the line or assign a background voice to the visible lead. Stage directions are not spoken words. A reference still cannot establish voice identity, and an old voice approval applies only to its specific artifact and scope.

Before generating references, find existing applicable images and their approval status. Keep identity, costume, expression, pose, space, style and voice roles separate. Unknown appearance stays unknown until an authorized design choice is made; do not fill it with a different project's character. For a prompt-only request, identify missing assets without implicitly generating media. For authorized reference creation, route to [character visual development](character-visual-development.md) and [shot reference planning](shot-reference-planning.md). Apply [video adapters](video-adapters.md) for immutable asset binding, current provider verification and deny-by-default borrowing.

## Reconcile changes without rewriting history

Keep an active correction with its exact target, decision source and superseded interpretation. A one-line speaker correction, one-scene style change or one rejected audio file is not a global rule. Invalidate dependent biographies, dialogue, references, boards or prompts when the bound fact changes; preserve unaffected approved material. An index saying “fixed” does not demonstrate that a delivered video contains the fix.

Extract only the general failure mechanism, applicable condition and observable check into the skill, following [publication boundary](publication-boundary.md). Test a second, independently invented case and a case that should remain unchanged. Report mechanical consistency, semantic review and actual media review separately; none proves that all source history was recovered.
