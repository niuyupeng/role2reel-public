# 题材、画风与平台研究

## 中英文检索与语言适配

研究语言由用户需求与目标市场决定；中文与英文可作为双语检索示例，不排除其他语言。用于寻找角色造型技能、故事/音乐视频方法、平台案例及模型资料时，同一核心问题分别使用中文和英文检索，并按各自语境调整术语，而非只把搜索词直译。窄范围执行、纯改字或用户已给定充分资料的任务不为凑双语而重复调研。

- 示例词组：角色设定/体态三视图/表情设定 ↔ character design sheet / turnaround / expression sheet；三维水墨/水墨动画 ↔ 3D ink wash animation；连续叙事/对白入歌 ↔ narrative continuity / dialogue-to-song transition。这些是检索种子，不是已验证热门词。
- 记录两种语言实际查过的查询词、来源链接、内容语言、日期、可访问范围及采用/舍弃理由。翻译页、镜像和互相转载去重，不充当独立交叉证据。某侧没有合适资料就明确缺口，不编造平衡，不按语言凑数量。
- 按原作者材料、官方说明、可核验作品与实际适用性选取；不把英文、中文、作者国籍或GitHub星数当质量保证。涉及最新能力时核对日期与版本，发生矛盾保留具体证据与适用范围。
- 资料语言不等于目标受众。抖音/B站与YouTube分别评估叙事习惯、笑点、声音、字幕和发布入口；外语案例的方法需适配目标受众的故事，不能直接迁移流量结论，也不能覆盖用户已定画幅、美术和角色。
- 研究总结使用用户工作语言，关键术语可附英文以便追溯。可执行生图/视频提示词依据当前模型文档或实际试验选中文或英文，不预设“英文更强”。平台能力未知时保留用户工作语言；有必要对比才给语义一致的双语版本，清楚标出实际提交版，避免把两份重复粘入同一输入框。
- 翻译提示词时保留资产ID、时间码、动作因果、镜头关系及限制；原角色名、原歌词与指定对白保持原文，不因英文提示词改成英语演唱或配音。语言试验未实际执行前只能称候选。

## 研究应改变决策

先写本轮要决定什么，例如“哪种开场能让科研圈外的人理解这句歌词”，再检索。关键词交叉：受众（研究生/打工人等）×处境（返工/下班/告别等）×形式（角色说唱/表演/MV/循环动画）×平台。官方资料用于平台能力与口径，创作者作品用于观察创作方法；同行的运营论断不能当算法事实。

研究规模随问题：快速选题可看少量可验证样本；用户要求广泛调研时，起步目标是跨平台12—18条相关作品，并为候选形式补普通表现或同作者常态对照。这个数是工作采样目标，不是统计显著性门槛。无法访问时记录缺口，不能填充虚构作品凑数。

每条记录：URL、作者、作品发布时间、检索日期、平台/入口、时长、能观察的媒体范围、单条指标与计数单位、同账号对照、实际观察、可迁移方法、不可借用元素、限制。访问状态取 `full_av` / `frames_only` / `metadata_only` / `search_snippet` / `unavailable`。只有完整视听或明确时间窗的实际观察才支持该范围的镜头/听感判断；封面不能证明运镜。

近期窗口先按需求定义（如近30天），不足可扩到90天并标记；经典案例另列。再使用热点前重新检查日期和走势。播放量不等于点赞数，合集不等于单条，高绝对量不等于高于账号常态。不能由一次高表现推出画风的因果效果。

## 指定作品的身份与访问核验

用于用户提供分享口令、短链接或精确作品要求时。核验来源与访问范围，不运行一次性批量探测流程。

1. 保留原链接/口令，记录从原始入口到落地页的实际跳转。先用原链接，再沿可见作者主页或平台搜索按标题与作者定位；不要通过裁短口令、猜测ID或穷举URL把另一作品当目标。
2. 将原始链接、实际作品URL、作品ID、作者/账号、标题/集数和各字段的来源绑定为同一候选。只从已观察到的页面、官方响应或用户材料取得字段；未知留空。标题、作者和ID发生矛盾时保持待核验，不能靠关键词得分抵消矛盾。
3. 搜索摘要、网页状态、元数据、可播放性、完整视听观察是不同证据层。HTTP 200、跳回平台首页、拿到HTML或关键词命中均不证明找到作品；媒体探测能证明存在音视频流，也不能单独证明作品身份或实际听看过。保留前述访问状态字段。
4. 逐候选保留来源，不能把跨页面抓到的媒体地址统一配给“最像”的一条。转载、翻译或第三方解析结果仅作线索，不能因服务名称或中继返回成功就标成可信原作；引用回到可核验的原始作者/作品。
5. 一个有效入口与一个有依据的替代入口仍无法取得目标时，记录当前缺口与停止原因；没有新线索不重复试验。需要视听判断时请用户提供原片或可访问的确切链接，能做的元数据整理继续做，但不拿相似作品顶替。旧的代理列表、关闭证书校验、签名猜测与口令穷举不继承为日常技能能力。
6. 失败也保存：尝试日期、原始入口、落地结果、身份冲突、访问层、实际结论与恢复所需输入。仅存必要证据，分享记录不携带登录Cookie或临时凭据。下载、导出或后期处理按当前工具规则及任务授权执行，合并历史代码不构成执行授权。

简洁记录可用：`原始入口 → 实际落地/作品ID → 作者和标题依据 → 访问范围 → 可支持的判断 → 未知/下一输入`。媒体与画面已可直接访问时，不为填表重跑恢复流程。

## 选题卡

每个候选写：谁在什么时刻会在意；一句内容承诺；原歌词支持/需新写歌曲；首屏动作；视觉回报；最低资产；制作难点；系列下一集；证据和反例；本次主变量。先淘汰与角色/歌曲冲突的方向，再按受众相关性、音乐记忆点、画面清晰度、可重复生产能力比较。可用文字高/中/低及理由，不计算“爆款概率”。

内容结构可选：处境共鸣→反击句；日常尴尬→可爱化解；压抑→释放；一件道具贯穿；季节/节庆→角色自己的经历；一个动作循环→一句歌词记忆；作品成片→创作过程。它们是创作框架，不是当前热榜。直播大主播的销售口播套路不直接套到音乐IP。

## 平台与入口要分开

|入口|设计起点（待验证策略）|交付|主要观察|
|---|---|---|---|
|抖音竖屏推荐流|开场尽快让人辨认主体、处境和正在发生的动作；画面服务歌曲钩子|竖屏构图、首屏、歌词字幕计划、独立封面、自然互动句|当前后台可见的留存、观看时长、分享与关注；记录分母|
|抖音搜索/主页|标题和封面清楚说明是哪首、哪一集、什么处境|搜索语义明确的标题、系列标记和统一视觉|同入口曝光与点击，不能与推荐流混算|
|Bilibili 推荐/搜索音乐稿件|让标题、封面和作品内容兑现同一个承诺；完整版本可保留铺垫和音乐回收|按当前投稿入口适配横/竖版；词曲/演唱/视觉分工、准确AI使用说明|点击、观看时长、币/藏/评/关注分别记录|
|YouTube Shorts|直观动作适配小屏；跨语言时降低文字梗依赖|竖屏、目标语言标题/字幕、能独立理解的开头和结尾|选择观看/划走、平均观看时长/比例等当前后台指标|
|YouTube 常规视频|区分点击包装和观看体验，标题与缩略图互补|独立横版封面、标题、简介及长短版本关系|同入口CTR、观看时长及留存，不套用Shorts指标|

上述是设计建议，不是平台强制画风、时长或算法权重。规格、封面入口、标题上限、AI标识及音频使用条件按发布当天官方文档或实际界面确认。YouTube官方明确Shorts并不偏爱某个特定格式，表现与观众匹配共同影响推荐（见来源表）。

## 画风选择板

先固定IP身份，再比较材质、轮廓、光线、背景复杂度和镜头距离，不同时改脸型与画风。

|风格候选|适合表达|图片要求|常见失败|
|柔软绒毛3D|可爱外形与有锋芒歌词的反差|眼睛清楚、毛发轮廓稳定、衣服与背景分离|毛发闪烁，萌感掩盖处境|
|2D平涂/赛璐璐|表情、动作夸张及图形化节拍|明确剪影、统一线宽、简洁色块|转头变脸，线条跳动|
|黏土/定格质感|手工趣味、笨拙可爱、荒诞日常|统一材质，动作幅度和帧感明确|材质突然写实、塑形漂移|
|纸艺/拼贴|歌词意象、章节转折|层级、纸张边界和运动层明确|拼贴板被当成多个角色|
|舞台电影光|演唱存在感和副歌释放|脸、手、话筒可辨；光线有方向|暗光遮脸、光效吞掉动作|
|日常空间中的风格化角色|具体生活共鸣|尺度、接触阴影和透视一致|角色漂浮、背景过细抢主体|

选图先看“缩成手机缩略图后是否读得懂”，再看角色一致性、动作起点是否可执行、道具握持、空间方向、裁切/字幕余量。不要仅按最漂亮或最新一张选择。没有样本支持时明确“候选风格”，不能称平台最热门。

## 发布后的验证

每轮预先选一个主要问题和指标；封面实验与首屏实验分开。记录实际观察窗口、平台、入口、时长、账号阶段；关注新粉是否记住角色而非只记住热点。多次改变题材、歌曲、封面和时长时不能称严格A/B。缺失指标留空；不虚构统一完播合格线或最佳发布时间。
